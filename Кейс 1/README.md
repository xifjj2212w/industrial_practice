# Кейс 1. Поиск нетипичного поведения заявок на закупку

Папка содержит полное решение учебного кейса: журнал событий, воспроизводимый
код анализа, итоговый `anomalies.csv`, отчёт и описание кейса с решением.

├── Описание_кейса_и_решения.md    — постановка задачи, методика и разбор решения
├── README.md                      — этот файл
├── analysis/
│   ├── analyze.py                 — весь анализ: правила, проверки, выгрузка CSV

├── data/
│   └── students.csv               — исходный журнал (12 162 события, 1 000 заявок)
├── docs/
│   ├── task.md                    — условие кейса

## Как воспроизвести

Нужен Python 3.10+ и pandas (проверено на Python 3.12, pandas 3.1).

```powershell
cd "Кейс 1"
python analysis/analyze.py
```

Скрипт перезапишет `anomalies.csv` и `analysis/metrics.json` и напечатает
сводку: число событий и заявок, распределение по типам, длительности этапов,
количество строк по каждому типу отклонения. Дополнительные параметры:

```powershell
python analysis/analyze.py --data data/students.csv --out anomalies.csv
```

Проверки внутри скрипта: все `ProcessInstanceId` существуют в журнале, строки
не дублируются, открытые заявки не попадают в правило «пропуск руководителя».

## Правила поиска аномалий

| № | AnomalyType | Критерий | Строк |
|---|---|---|---|
| 1 | Пропуск согласования руководителем | заявка завершена `fulfilled`, этапа «Согласование руководителем» нет | 16 |
| 2 | Исполнение до согласования бюджета | «Исполнение заявки» закрыто раньше «Согласования бюджета» | 8 |
| 3 | Юридическая проверка после исполнения | для `contract`: «Проверка договора» позже «Исполнения заявки» | 3 |
| 4 | Дублирование проверки заявки | две «Проверки заявки» подряд без возврата на доработку | 8 |
| 5 | Самосогласование заявки | этап руководителя закрыл сам инициатор процесса | 2 |
| 6 | Подмена роли при согласовании | этап руководителя закрыл пользователь с ролью `requester` | 6 |
| 7 | Чрезмерные возвраты на доработку | 5 и более возвратов в одной заявке | 8 |
| 8 | Двойная внеплановая проверка | две внеплановые проверки аудитора в одной заявке | 8 |
| 9 | Аномально долгая проверка заявки | задание «Проверка заявки» дольше 100 часов | 8 |

Порог 100 часов для правила 9 выбран по данным: медиана этапа 0,4 ч,
99-й перцентиль 23 ч, минимальное значение среди подозрительных заданий —
198 ч (8,25 календарных дня). Порог 5 возвратов: в журнале 119 заявок с одним
возвратом и ни одной с двумя-четырьмя.

## Что не считается аномалией

- 10 открытых заявок на дату среза — нормальное незавершённое состояние;
- 51 отклонённая заявка — штатный результат согласования;
- длительности, включающие ожидание и выходные, — сами по себе не нарушение;
- участие аудитора как таковое — редкость не является доказательством нарушения,
  поэтому отдельно проверяется только двойная проверка в одной заявке.
