# Кейс 2. Восстановление процесса по журналу событий

Папка содержит полное решение кейса: исходный журнал, воспроизводимый код,
схему процесса, таблицу вариантов, CSV переходов, отчёт и описание решения.

## Как воспроизвести

Нужен Python 3.10+, pandas и matplotlib (проверено на Python 3.12, pandas 3.1,
matplotlib 3.10).

```powershell
cd "Кейс 2"
python analysis/analyze.py
python analysis/make_schema.py
```

`analyze.py` перезапишет `variants.csv`, `transitions.csv` и
`analysis/metrics.json`, напечатает сводку и все восемь вариантов.
`make_schema.py` перерисует `schema/process_schema.png` и `.mmd`.

Встроенные проверки: 1 000 стартов и 1 000 финишей, каждый маршрут начинается
с «Регистрации заявки» и заканчивается одним из трёх финальных событий, сумма
вариантов равна 1 000, все переходы взяты из фактических пар.

## Что получилось

- 10 активностей: регистрация, первичная проверка, согласование руководителем,
  проверка бюджета, дополнительное согласование, исполнение закупки, доработка
  и три финальных события.
- 12 переходов, 8 вариантов. Основной маршрут — 567 заявок (56,7%).
- 174 возврата на доработку в 156 заявках: 138 — один возврат, 18 — два.
- Дополнительное согласование — 209 заявок, только при сумме от 150 614,59;
  18 из 227 крупных заявок прошли без него.
- Окончания: 911 «Заявка выполнена», 63 «Заявка отклонена», 26 «Заявка отменена».

## Что не утверждается

- Условие суммы для дополнительного согласования — статистическая гипотеза,
  а не факт из журнала: 18 крупных заявок прошли без этапа.
- Причина отмены по журналу не восстанавливается: видно только, что результат
  `cancel` фиксируется на этапе руководителя.
- Длительности между событиями включают ожидание и не равны времени работы,
  поэтому выводов о скорости этапов в отчёте нет.
